# std::move
메모리 복사가 일어나는 것이 아니라 객체를 RValue로 취급한다. (곧 사라짐. 임시 객체)
`std::move`가 호출되면 복사가 아니라 **이동 생성자**가 호출 된다.

## 1. 개념

* **복사:** 새 메모리 할당 + 전체 내용 복사
* **이동:** 원본의 데이터 포인터만 복사 + 원본 포인터 nullptr로 설정

그렇다면 스택 메모리에 있는 객체에는 `std::move`를 사용하면 안된다고 생각할 수 있는데, 예를 들어 벡터에 스택 메모리에 선언된 `std::string`을 삽입하려할 때 `std::move`버전의 삽입 함수를 호출한다면 스택 메모리 내의 `std::string` 객체의 메모리가 벡터 내에 복사되고, 기존 스택 메모리에 있던 객체가 가리키던 문자열 포인터는 `nullptr`로 설정되어 자연스럽게 문자열의 소유권이 벡터 내에 새로 생성된 객체로 이동한다. 

이 때 `std::string`의 이동 생성자의 내용은 기존 객체 자신의 메모리를 이동 대상으로 복사한 후, 기존 객체가 사용하던 멤버 객체 중 힙을 가리키던 멤버들을 `nullptr`로 만드는 동작을 수행한다.

때문에 사용자 정의 객체가 **이동**이 가능할 예정이라면 이동 생성자를 잘 구현해야겠다. 

## 2. 주의사항
* 1) 이동 후 원본은 빈 껍데기가 된다. 호출 이후 접근해선 안된다.
* 2) 이동 생성자와 이동 대입 연산자가 존재해야 한다.
* 3) 남용하면 컴파일 최적화를 방해할 수 있다. (이동생성자 호출을 없앨수도 있었음)

## 3. 이동 생성자 암시적 생성 규칙
클래스에 다음 중 하나라도 직접 정의하면 컴파일러는 이동 생성자를 암시적으로 만들지 않는다. 객체에 이동 생성자가 없는 경우에는 `std::move`를 사용하면 복사 생성자가 호출된다.
* 복사 생성자
* 복사 대입 연산자
* 이동 대입 연산자
* 소멸자
